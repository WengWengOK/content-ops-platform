## 二、已补齐的差距（本轮工程成果）

1. **编排韧性**：进程崩溃后自动恢复续跑（实测 kill 后重启自愈）；状态以 PG 为唯一事实源
2. **可靠事件**：阶段事件 Outbox 落库（PENDING→PUBLISHED），审计/回放/Kafka 迁移就绪
3. **对外接入**：标准 MCP JSON-RPC（6 个工具：热点/工作流/RAG），任何 MCP 客户端可调
4. **链路可观测**：workflow.stage → llm.call 多层 span，traceId 贯通「自定义 trace 表 + Jaeger + 审计」
5. **评测闭环**：判官 Agent 对阶段产物自动打分落库，CI 用同一套接口做回归门禁
6. **治理**：JWT 角色（ADMIN/CREATOR/VIEWER）即时生效、审计留痕关联 traceId
7. **部署**：前后端容器化、compose 全家桶（含 Jaeger/Prom/Grafana 自动接入 OTLP）

## 三、仍存在的差距（按优先级）

### P0（规模化前必须）

1. **服务化拆分未落地**：仍是单机单实例。编排器/Agent Worker/Tool Services 拆容器后，
   才能水平扩容与故障域隔离（拆分契约已在 docs/ARCHITECTURE.md 就绪）
2. **长期记忆与上下文工程缺位**：无跨会话用户/账号记忆、无上下文压缩与结构化缓存，
   这是 2026 大厂 Agent 的标配（对话续改目前依赖会话级 ChatMemory）
3. **评测集规模与自动化**：当前评估集 2 条、无标注回流；需 50-100 条按阶段/平台覆盖 +
   真实线上样本沉淀 + LLM-as-Judge 与人工标注对齐校准

### P1（体验与稳定性）

4. **OTel 全链路埋点覆盖不全**：HTTP/LLM/阶段已埋，工具调用（MCP tools/call）、
   RAG 检索、任务队列尚未全部 span 化
5. **RAG 工程化**：向量库仍以进程内/单机为主，缺分片、增量索引、权限过滤、效果 A/B
6. **云原生编排**：无 K8s/Helm、无 HPA、无滚动发布/金丝雀；Grafana Alerting 已有，
   但缺 SLO/错误预算体系
7. **多租户完善**：订阅/合集按 owner 隔离，但作品下载、文件存储、审计归属等仍有匿名兜底，
   生产需强制登录 + 全链路租户校验

### P2（大厂特色）

8. **Agent 自我改进闭环**：评测失败自动触发优化迭代（优化 Agent 已存在，未接自动回路）
9. **多模型路由自动化**：按任务难度/成本动态路由 + 模型网关（当前为阶段静态配置）
10. **企业级集成**：SSO/OIDC、数据脱敏审计、合规导出

## 四、结论

项目已从「功能型 MVP」走到「**内部生产级候选**」：核心工程底座（编排韧性、事件总线、
MCP、OTel、评测门禁、RBAC、容器化）对标大厂已无明显缺口，**综合底座评分 7.0/10**。

距「对外规模化」（9 分）的差距集中在三点：**服务化拆分与水平扩展、长期记忆/上下文工程、
评测集规模化**。按 docs/ARCHITECTURE.md 的顺序（先 Tool Services → 再 Worker → 最后编排器）
推进，配合记忆层与评测数据回流，即可进入规模化阶段。
